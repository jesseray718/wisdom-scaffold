# Contributing to [PROJECT NAME]

Thank you for your interest in contributing to [PROJECT NAME]! [BRIEF DESCRIPTION]

This project follows the OpenRoot cathedral-uplift conventions: no gatekeeping, real gains tracked alongside monetary gains, and every contribution lifts the next climber.

## How to Contribute

1. **Open an issue first** for anything beyond a trivial fix, so the change can be discussed before work begins.
2. **Fork the repository** and create a feature branch (`git checkout -b feature/short-description`).
3. **Make focused changes.** Keep pull requests small and scoped to a single concern.
4. **Test your changes** locally before opening a pull request. If the project has no automated tests yet, describe how you verified the change manually.
5. **Open a pull request** against `main` (or the repository's default branch) with a clear description of what changed and why.

## Code Style

- Match the existing style and structure of the file you are editing.
- Prefer absolute paths and deterministic behavior over implicit assumptions (OpenRoot convention).
- Document non-obvious logic with comments only where necessary.

## Reporting Issues

- Use the issue templates in `.github/ISSUE_TEMPLATE/` when filing bugs or feature requests.
- Include reproduction steps, expected behavior, and actual behavior for bugs.

## Review Process

- Maintainers will review pull requests as time allows. There is no formal SLA for this project.
- Approved changes are merged once they align with the project's goals and don't regress existing functionality.

## Code of Conduct

By participating in this project, you agree to abide by the terms in [GOVERNANCE.md](../GOVERNANCE.md).
